# Successful Patterns

## 模块化设计

**描述**
每个模块独立，通过 frontmatter 声明依赖，删除任一模块不影响其他。

**效果**
- 维护成本低
- 测试简单
- 扩展方便

**验证**
- [x] 2026-05-24: 新增15号模块，未影响其他模块

**应用**
所有新模块必须满足此标准。

## 数据新鲜度检查

**描述**
每次生成报告前检查数据新鲜度，过期数据自动阻止报告生成。

**效果**
- 防止基于过期数据的决策
- 强制数据维护
- 提高报告可信度

**验证**
- [x] 2026-05-15: 实现 check_freshness.py
- [ ] 待验证：过期时是否真正阻止生成

**应用**
每次生成报告前必须执行。

## 配置驱动输出

**描述**
报告内容、深度、风格全部由 config.yaml 控制，不修改代码。

**效果**
- 灵活性高
- 无需编程知识即可定制
- 可复用配置

**验证**
- [x] 2026-05-15: 实现 config.yaml 驱动

**应用**
新增主题时复制配置即可。

## 铲子股优先原则

**描述**
优先配置设备/材料/零部件供应商（铲子股），而非终端产品公司。

**效果**
- 风险较低（无论谁赢都需要铲子）
- 确定性强
- 符合投资逻辑

## 完整版报告生成流程

**描述**
15个模块全选，L3深度，从数据检查到报告输出的完整流程。

**流程**
1. check_freshness.py 检查数据新鲜度
2. update_data.py 更新过期数据
3. 再次检查确认数据新鲜
4. 按 config.yaml 生成完整报告
5. 写入 output/ 目录
6. 记录进化分析

**效果**
- 60页深度报告生成成功
- 数据新鲜度保障
- 完整记录可追溯

**验证**
- [x] 2026-05-24: 成功生成 output/孙哥方向-2026-05-24-L3-散户科普风.md
- [x] 15个模块全部启用无冲突
- [x] 数据更新流程顺畅

**应用**
标准报告生成流程，每次使用。
