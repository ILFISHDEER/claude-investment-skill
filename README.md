## 快速开始

### 第一步：配置

打开 `config.yaml`，修改以下字段：

```yaml
theme:
  name: "你要分析的主题"      # 如：孙哥方向产业链全景梳理
  id: "theme-id"              # 唯一标识，如：sun-ge-direction

output:
  depth: "L3"                  # L0/L1/L2/L3/L4，建议从 L3 开始
  style: "专业投行风"           # 专业投行风/口语化风/路演PPT风/散户科普风
  market_focus: "中美双线"     # 美股/A股/港股/中美双线/全球

modules:
  enabled:                   # 只保留需要的模块，建议全选
    - "00-市场情绪分析"
    - "01-市场环境扫描"
    # ... 其他模块
```

### 第二步：生成报告

对 AI 说：
> "按 config.yaml 配置，生成投资分析报告"

### 第三步：数据维护

```bash
# 每周更新股价数据
python update_data.py

# 每周健康检查（生成红黄灯预警）
python maintenance.py --review monthly

# 每季度审议（生成剔除/纳入建议）
python maintenance.py --review quarterly
```

## 完整工作流

```
日常维护（每周）
    │
    ├── python update_data.py          # 更新股价数据
    ├── python maintenance.py --review monthly  # 健康检查
    └── 查看 reports/健康检查-*.md     # 处理红黄灯预警

    │

    ├── 更新 tickers.yaml              # 执行剔除/纳入
    ├── 更新 changelog.yaml            # 记录变更
    └── 更新 backtest/                 # 记录预测vs实际

报告生成（按需）
    │
    ├── 修改 config.yaml               # 配置主题、深度、风格
    ├── AI 生成报告                    # "按 config.yaml 生成报告"
    └── 输出到 output/                 # 获得最终报告
```

## 股票库维护机制（v2.2核心功能）

### 为什么要维护股票库？

- 行业格局会变（技术路线被颠覆）
- 公司基本面会变（财务恶化、管理层变更）
- 估值会变（泡沫破裂或价值发现）
- 新标的会出现（IPO、技术突破）

### 自动评分体系

```python
# 6维100分制评分
total_score = price_20% + valuation_20% + financial_20% + 
              technology_20% + catalyst_10% + risk_10%
```

| 等级 | 分数 | 动作 |
|------|------|------|
| 🚨 D级（红灯） | <60 | 强制剔除候选，进入 changelog |
| ⚠️ C级（黄灯） | 60-69 | 观察名单，下季仍<70则剔除 |
| 🟡 B级 | 70-79 | 观察改进，需关注 |
| 🟢 A级 | 80-89 | 标准持仓，正常跟踪 |
| 🟢 A+级 | 90-100 | 核心仓位，重点配置 |

### 维护命令详解

```bash
# ========== 月度健康检查 ==========
# 快速扫描所有股票，生成红黄灯预警报告
# 耗时：2-3分钟（取决于股票数量）
python maintenance.py --review monthly

# 输出：reports/健康检查-2026-05-15.md
# 内容：
#   - 所有股票评分排名
#   - 红灯预警列表（需立即关注）
#   - 黄灯预警列表（进入观察名单）
#   - 评分维度明细


# ========== 季度审议 ==========
# 深度评估，生成剔除/纳入建议
# 耗时：3-5分钟
python maintenance.py --review quarterly

# 输出：reports/季度审议-2026-Q2.md
# 内容：
#   - 剔除建议清单及理由
#   - 纳入建议（从 candidates.yaml）
#   - 组合优化建议（权重调整）
#   - 执行检查清单


# ========== 预览模式 ==========
# 不写入文件，仅打印到屏幕
python maintenance.py --review monthly --dry-run


# ========== 单个方向评估 ==========
# 只评估某个方向（如量子计算）
python maintenance.py --direction quantum --review quarterly
```

### 维护文件说明

| 文件 | 用途 | 手动/自动 |
|------|------|----------|
| `tickers.yaml` | 当前股票池 | 手动更新（季度审议后）|
| `valuation.yaml` | 自动估值数据 | 自动（update_data.py）|
| `candidates.yaml` | 候选池 | 手动维护 |
| `changelog.yaml` | 变更历史 | 手动更新（执行变更后）|
| `reports/健康检查-*.md` | 月度报告 | 自动生成 |
| `reports/季度审议-*.md` | 季度报告 | 自动生成 |

### 剔除决策流程

```
maintenance.py 报告红灯
        │
        ▼
人工复核：是否触发强制剔除条件？
        │
        ├── 是（退市/造假/技术证伪）
        │       │
        │       ▼
        │   立即剔除：
        │       1. 从 tickers.yaml 删除
        │       2. 更新 changelog.yaml
        │       3. 记录剔除理由
        │
        └── 否（只是暂时低迷）
                │
                ▼
            进入观察名单（candidates.yaml 或 watchlist）
                │
                ▼
            下季度重新评估
```

### 纳入决策流程

```
发现新标的
    │
    ▼
加入 candidates.yaml
    status: research
    research_notes: "需验证..."
    │
    ▼
研究验证（技术、财务、估值）
    │
    ▼
更新 status: ready
    │
    ▼
季度审议会议
    │
    ▼
正式纳入：
    1. 添加到 tickers.yaml
    2. 记录到 changelog.yaml
    3. 初始评分录入
```

## 深度核心逻辑库（v2.4新增）

### 为什么需要深度分析？

`tickers.yaml` 中的一句话描述（如"刻蚀设备国产替代"）只告诉了**是什么**，但没回答：
- 它怎么赚钱？（商业模式）
- 为什么它能赢？（竞争格局）
- 技术壁垒在哪？（护城河）
- 什么时候兑现？（催化剂）
- 什么会毁掉它？（风险点）

### 10维度深度分析

每个股票的深度分析包含：

1. **一句话总结** — 电梯演讲
2. **商业模式** — 收入来源、成本结构
3. **竞争格局** — 市场份额、护城河
4. **技术壁垒** — 核心技术、研发强度
5. **产业链位置** — 铲子/终端/基建
6. **催化剂日历** — 未来6-12个月事件
7. **风险矩阵** — 概率×影响×对冲
8. **估值逻辑** — PE/PS/DCF、合理区间
9. **可比公司** — 国内外对标
10. **投资结论** — 评级、目标价、仓位

## 注意事项

### 模块系统

- `modules/` 中的文件头部有 frontmatter，不要删除
- frontmatter 包含模块元数据（名称、版本、依赖等）
- AI 根据 frontmatter 决定是否加载模块

### 数据维护（关键！）

> ⚠️ **重要**：报告基于数据生成，**数据过期 = 报告误导**

**更新频率要求：**

| 数据文件 | 更新频率 | 过期影响 | 检查命令 |
|----------|----------|----------|----------|
| `valuation.yaml` | **每周** | 股价偏差20%+ | `python check_freshness.py` |
| `catalysts.yaml` | **每两周** | 错过买入/卖出时机 | `python check_freshness.py` |
| `core_logic/*.md` | **每季度** | 基本面分析过时 | `python check_freshness.py` |
| `tickers.yaml` | **按需** | 公司信息相对稳 | 人工检查 |

**标准工作流程（每次生成报告前必须执行）：**

```bash
# 第1步：检查数据新鲜度
python check_freshness.py
# 如果显示 🚨 过期，必须先更新数据！

# 第2步：更新数据（如有过期）
python update_data.py

# 第3步：再次检查确认
python check_freshness.py

# 第4步：生成报告（确认数据新鲜后）
# 对AI说："按 config.yaml 生成报告"
```

**数据新鲜度检查：**

```bash
# 快速检查（控制台输出）
python check_freshness.py

# 生成详细报告
python check_freshness.py --report

# 检查特定主题
python check_freshness.py --theme 孙哥方向
```

**输出示例：**

```
📊 检查主题: 孙哥方向
  🔴 关键 valuation.yaml: ✅ 新鲜 (2天前)
  🟡 重要 catalysts.yaml: ⚠️ 警告 (18天前)
  🟢 一般 tickers.yaml: ✅ 新鲜 (25天前)
  🟡 重要 core_logic/*.md: ✅ 新鲜 (30天前)

⚠️  发现过期数据，建议立即更新
```

**重要提示：**
- 🚨 **严重过期**（valuation.yaml >14天）：股价可能偏差20%以上，报告无效
- ⚠️ **警告**（catalysts.yaml >14天）：事件时间可能已过期，可能错过买入时机
- ✅ **新鲜**：数据可信，可以生成报告

**自动阻止机制：**

如果数据严重过期，`check_freshness.py --report` 会返回错误码，阻止报告生成。

**为什么这很重要：**

假设 valuation.yaml 是7天前的：
- 英伟达7天可能涨跌15%
- 你的PE计算完全错误
- 买入/卖出建议可能完全相反
- **基于过期数据的决策 = 亏钱**

**最佳实践：**
1. 设置每周一早上自动运行 `update_data.py`
2. 生成报告前先运行 `check_freshness.py`
3. 看到 🚨 或 ⚠️ 必须先更新，再生成报告
4. 把数据新鲜度报告加入工作流

### 回测机制

- `backtest/` 每季度必须更新
- 格式：`{季度}-预测.md` 和 `{季度}-结果.md`
- 对比预测 vs 实际，修正方法论

### 反模式记录

- `antipatterns/` 是你最重要的知识资产
- 遇到错误判断立即记录，避免重复犯错
- 格式：错误描述 + 原因分析 + 改进措施

### 股票库维护

- **机器负责**：数据异常预警、自动评分
- **人负责**：逻辑验证决策、候选股研究
- **协作原则**：铲子股优先保留，概念股优先剔除

## 故障排除

| 问题 | 原因 | 解决 |
|------|------|------|
| yfinance 报错 | 网络问题或代码错误 | 检查代码格式，A股加 `.SS`/`.SZ` |
| YAML 格式错误 | 缩进或特殊字符 | 用 YAML 验证工具检查 |
| 模块未加载 | frontmatter 损坏 | 检查 `---` 包围的头部 |
| 报告生成失败 | config.yaml 错误 | 检查 YAML 语法和路径 |
| 评分异常 | 数据缺失 | 检查 ticker 代码是否正确 |

## 最佳实践

1. **先跑维护，再跑报告**
   - 先生成健康检查，确认没有红灯股票
   - 再生成投资报告

2. **保持候选池活跃**
   - 每月浏览一次 candidates.yaml
   - 及时把研究完成的标的改为 ready

3. **记录变更理由**
   - 每次剔除/纳入都记录到 changelog.yaml
   - 这是你的投资轨迹，复盘时很有价值

4. **定期清理 reports/**
   - 月度报告保留最近 3 个月
   - 季度报告永久保留

5. **版本控制**
   - 关键变更后 git commit
   - changelog.yaml 每次变更都提交
